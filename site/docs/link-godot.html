Link a Godot project

Linking connects your Leveldot project to a Godot game so that Save (Ctrl+S) also exports your levels into the game.

You need: a Godot project that uses Godot 4.4 or later (any 4.x from 4.4 on), and a saved Leveldot project. Leveldot itself does not need Godot installed.

What Link does

  • installs the Leveldot Bridge addon into the game (res://addons/leveldot_bridge/) and enables it in project.godot;
  • chooses the folder each level is exported to;
  • reads the game's entity types, if it has any yet;
  • exports the project once.

It adds nothing else: your own scenes and scripts are never changed. Leveldot remembers the linked game for the project.

First time

  1. Save the project (Ctrl+S). Link needs a saved project.
  2. In Leveldot choose File → Link Godot Project… and pick the folder that holds your game's project.godot. When the first export has worked, a summary says what was done. If it fails, the message says what to fix; press Ctrl+E to export again.
  3. Open the game in Godot (File → Open in Godot does it). If Godot already had the game open, choose Project → Reload Current Project once, so that it loads the addon.
  4. In Godot open the Leveldot screen (at the top, beside 2D / 3D / Script) → Levels, select your level and press Create Game Scene…. This makes a scene of your own that shows the level. If it asks you to refresh first, press Refresh and wait for the import to finish.
  5. Put your player, enemies and scripts into that scene, not into the generated level.

Every day

  • Ctrl+S (Save) exports every level of a linked project in the background. Saving a Leveldot project inside a Godot game also links it when there is no remembered export folder. Godot picks up the export and rebuilds the level scenes by itself — even while unfocused or on another monitor; your own scenes keep their nodes. A scene with unsaved changes is left alone, and Godot says so.
  • Ctrl+E (Export to Godot) saves unsaved changes and exports. Use it to export again without editing. If an export is already running, the latest saved version is queued for the next export.
  • What you see after Save or export — in Godot, a compact status button on the top toolbar (visible from 2D, 3D, Script and every other screen) and editor toasts show when a level is importing, refreshing, refreshed (with time to the second and duration), refreshed with warnings, skipped (automatic refresh off), or failed (plain cause and next step). Clicking the status button opens the Leveldot screen at that level. In Leveldot, the status bar confirms once Godot refreshes the export (or reminds you after about 20 seconds if Godot has not picked it up yet).
  • F5 (Play Level) saves, exports and starts the game at the level you are editing. It needs one successful export and a scene of the game that shows the level (step 4). Without one, Leveldot uses the game's main scene when that scene instances a level (or its script loads a generated world / uses LeveldotLevels) and the level you are editing is in the game's level list (a level gets listed once it has a Player Start, a Level Exit or a reaction that goes to a level). If one Player Start is in your selection, you start there. Pressing F5 inside Godot runs the game's main scene instead.

Where files go

  • res://leveldot/generated/ — written by Leveldot and the addon; never edit anything in it. Each level's export has its own folder, levels/<level name>/ (the name is made file-safe the first time and gets a number if another level already uses it). Godot imports its world.glb and the addon builds generated_world.tscn beside it. The addon also writes entity_types.json (your game's entity types, for Leveldot) and, once a level has a Player Start, a Level Exit or a reaction that goes to a level, levels.tres (the game's level list).
  • res://leveldot/entities/ — your entity types (Leveldot screen → Entities → New Entity… writes here).
  • res://leveldot/levels/ — where Create Game Scene… suggests saving your scenes.
  • res://addons/leveldot_bridge/ — the addon. Leveldot updates it when you export with a newer version.

Keep your own scenes and scripts outside generated/. Keep exports out of any folder that holds a .gdignore file: Godot does not import such folders.

Common problems

  • "Save the project first" — press Ctrl+S, then link again.
  • Godot older than 4.4 — the addon needs Godot 4.4 or later. Open the game in a newer Godot.
  • Godot does not react to an export — the game must be open in Godot with Leveldot Bridge switched on under Project → Project Settings → Plugins. Reload the project once after linking. You can also press Refresh on the Leveldot screen's Levels page.
  • The level is not in the game — only a scene that contains the level's generated_world.tscn shows it. Use Create Game Scene… (step 4).
  • A201 — a file the export needs is missing, ignored by Godot (.gdignore) or not imported yet. The message names the file. Let Godot finish importing, or move the export folder, then export again.
  • X402 — the export and the addon do not match, or a file changed after export. If the message names export_schema_version, export again from Leveldot (it updates the addon); update Leveldot and the addon together.
  • X403 — a scene named generated_world.tscn that Leveldot did not write is in the way. Move or rename it.
  • X401 — a refresh stopped with a script error, or a generated file could not be written. Look at Godot's Output panel, export again; if it repeats, update the addon.
  • E302 — a reaction is malformed, or an entity that sends or receives events has a script without the event functions. Export again; make the entity extend LeveldotEntity.
  • E303 — a value stored in the level does not fit the entity's setting (for example it was renamed or changed type). The setting keeps its default; fix it in the script or the level.
  • E301 — the level uses an entity type whose scene is missing in the game. On the Leveldot screen's Levels page press Create … next to the missing type, or restore its scene. Then refresh.
  • A failed export keeps the level's previous export. With several levels, each is written in turn after a check of all of them: a failure later on does not undo a level already written. A failed refresh keeps the last generated scene and its colliders, but Godot may already show the new geometry from world.glb. Fix what the message says and export or refresh again.
